# Очередь сдачи лабораторной работы

Сайт для выбора места (порядка) сдачи лабораторной работы.
Backend — Python + Flask, хранилище — SQLite локально и Postgres на хостинге,
frontend — Vue 3 (без сборки, файлы лежат в `static/`).

## Быстрый старт

```bash
pip install -r requirements.txt
python init_db.py
python app.py
```

Сайт открывается по адресу `http://localhost:5000`.
Чтобы к нему подключались одногруппники по локальной сети, дайте им адрес
`http://<ваш IP>:5000` (сервер слушает все интерфейсы).

`init_db.py` заводит всех людей из `Люди.txt`. **Стартовый пароль у всех одинаковый — `a123456`**;
каждый участник меняет его сам на странице «Мой пароль» (старый пароль + новый дважды).
Пока пароль стартовый, сайт показывает предупреждение. Повторный запуск скрипта безопасен:
уже заведённым людям пароли не сбрасываются. Приложение заводит людей и само при первом
запуске, если база пустая.

Администратор — **Пархачева Екатерина Евгеньевна** (определяется автоматически по списку).

## Листы голосования

Всё расписание строится вокруг **листа** — это отдельное голосование за места
в очереди. У каждого листа своё:

* название и описание (их видят участники);
* состав людей — кто входит в это голосование;
* дни недели повторения и время приёма пожеланий (например, «по Вт, Чт с 18:30 до 19:15»);
* количество мест (по умолчанию — по числу участников листа).

Листов может быть сколько угодно, в том числе несколько в один день. Участник
видит на своей странице все свои листы: сначала те, что принимают пожелания
сегодня (по времени открытия), затем остальные. У каждого — своё название,
описание, расписание и свои три поля пожеланий, которые открываются ровно в
заданное администратором время.

При первом запуске создаётся лист «Лабораторная работа» со всеми людьми из
`Люди.txt`, ежедневно с 20:00 до 21:00. Дальше администратор заводит свои листы
на вкладке «Листы».

## Распорядок дня листа

| Время | Что происходит |
|-------|----------------|
| за 5 минут до открытия | Пожелания прошлых кругов стираются, лист готов к новому приёму |
| окно приёма (например, 20:00–21:00) | Участники листа выбирают и правят три желаемых места |
| после закрытия | Администратор формирует распределение и отчёт по листу |
| в любое время | Вход на сайт открыт всем: посмотреть очередь, своё место, договориться об обмене, сменить пароль |

Ограничение по времени касается **только пожеланий** — и участников, и администратора.
Подготовку выполняет фоновый поток; если сервер в этот момент был выключен, она
произойдёт при первом же обращении к сайту. Запоздалая подготовка стирает только
пожелания прошлых дней — то, что люди уже отдали в текущем круге, не трогается.
Кнопка «Подготовить лист заново» у администратора стирает и текущие пожелания.

## Что умеет участник

* войти по фамилии, имени и паролю в любое время суток (`Иванова Анна` + 7 символов,
  сначала `a123456`);
* сменить себе пароль: старый пароль и новый дважды (7 символов, латиница и цифры);
* видеть все свои листы на одной странице — с названием, описанием и расписанием;
* выбрать в каждом листе три разных желаемых места и зафиксировать их (в часы приёма);
* отредактировать или полностью удалить свои пожелания, пока идёт приём;
* видеть, кто из листа уже проголосовал, а кто ещё нет;
* после расчёта видеть всю очередь: кто на каком месте, чьё пожелание учтено,
  чьё нет и кого поставили автоматически по остаточному принципу;
* предложить конкретному человеку поменяться местами;
* согласиться на обмен или отказать; автор может отозвать своё предложение.

## Что умеет администратор

* создавать, изменять и удалять листы: название, описание, дни недели, время
  приёма, количество мест и состав участников (вкладка «Листы»);
* всё то же самое, что и участник, — он тоже входит в листы и получает место
  (вкладка «Мои пожелания», приём для него в те же часы);
* видеть по каждому листу, кто прислал пожелания, а кто нет;
* менять пароль любому участнику — сгенерировать случайный или задать вручную
  (ровно 7 символов, английские буквы и цифры);
* включить режим отладки, когда приём открыт круглосуточно во всех листах;
* запустить расчёт распределения по выбранному листу и дате;
* загрузить ранее скачанный отчёт обратно — распределение восстановится,
  участники снова увидят свои места (см. ниже);
* посмотреть отчёт и журнал, выгрузить их:
  * `Очередь_<лист>_ГГГГ-ММ-ДД.csv` — лист, место, фамилия, имя, отчество,
    пожелания, результат, дата формирования;
  * `Журнал_ГГГГ-ММ-ДД.log` — все события за день;
  * `Отчет_<лист>_ГГГГ-ММ-ДД.zip` — то и другое одним архивом.

## Загрузка отчёта обратно

Скачанный файл `Очередь_<лист>_ГГГГ-ММ-ДД.csv` можно вернуть на сайт:
вкладка **«Отчёт» → «Загрузить готовое распределение из файла»**. Это нужно,
если хостинг перезапустился и данные пропали, или если очередь поправили руками
в Excel.

Как это работает:

* лист и дата берутся из шапки файла; если листа с таким названием нет или дата
  не указана, их можно выбрать в форме вручную;
* люди сопоставляются по фамилии и имени; строки читаются по названиям колонок,
  поэтому файл можно править и переставлять в нём строки;
* поддерживаются кодировки UTF-8 и Windows-1251 (как сохраняет Excel),
  разделители `;` и `,`;
* если колонку «Результат» стёрли, статус восстанавливается по пожеланиям и
  номеру сработавшего пожелания;
* файл проверяется: повторяющиеся места, незнакомые люди, места за пределами
  листа и нечисловые значения отклоняются с указанием строки;
* прежнее распределение за эту дату заменяется, незакрытые заявки на обмен
  аннулируются, всё пишется в журнал.

## Алгоритм распределения

Задача — раздать каждому ровно одно место так, чтобы как можно больше людей
получили одно из трёх выбранных ими мест. Это классическая задача о назначениях.
Полный перебор для 26 человек нереален (26! вариантов), поэтому применяется
**венгерский алгоритм** (метод Куна — Манкреса, O(n³)): он даёт **ровно тот же
результат, что и перебор**, только мгновенно. В `test_all.py` решение сверяется
с настоящим перебором на случайных наборах.

Стоимость назначения подобрана лексикографически (`assignment.py`):

1. `MISS_W = 100000` — как можно меньше людей вообще без выбранного места;
2. `RANK_W = 1000` — среди остальных: сначала первое пожелание, потом второе, потом третье;
3. `DIST_W = 1` — кому места не хватило, того ставят как можно ближе к желаемому;
4. **очередь голосования** — если несколько раскладов одинаково хороши, выбирается
   тот, где пожелания точнее учтены у проголосовавших раньше, а ближайшие места
   вместо желаемых подобраны тем, кто проголосовал позже.

Приоритет по очереди устроен так: каждому голосовавшему даётся вес (чем раньше
отдал пожелания — тем больше), и штраф за его неудобства умножается на этот вес.
Множитель `tie_scale` заведомо больше любой суммы таких весовых добавок, поэтому
приоритет **никогда** не ухудшает основной результат: число учтённых пожеланий
и суммарное отклонение остаются оптимальными, приоритет лишь выбирает между
одинаково хорошими вариантами. Вся арифметика целочисленная, так что порядок
предпочтений соблюдается точно, без ошибок округления.

Пример из живой проверки: четверо выбрали одни и те же места 1, 2, 3.
Проголосовавшие первым, вторым и третьим получили места 1, 2 и 3, а четвёртому
(проголосовал последним) подобрали ближайшее свободное место 4. В журнале у
каждого записано, каким по счёту он голосовал.

Порядок действий:

1. люди, приславшие пожелания, расставляются венгерским алгоритмом оптимально;
2. кто не прислал пожелания до 21:00 — считается, что ему безразлично: такие
   участники случайным образом занимают оставшиеся места;
3. в журнал пишется поимённо, чьё мнение учтено (и какое по счёту пожелание
   сработало), а чьё нет (с указанием ближайшего желаемого места и отклонения),
   а также вся очередь голосования с временем подачи пожеланий.

Расчёт выполняется отдельно по каждому листу: свои участники, свои места, свой отчёт.
После расчёта участники видят очередь целиком (кто голосовал и чьё пожелание учтено,
а кого поставили автоматически) и могут по обоюдному согласию меняться местами —
обмен меняет места в готовом распределении и полностью протоколируется.

## Развёртывание на Render.com

В репозитории уже лежит всё нужное: `Dockerfile`, `gunicorn.conf.py`, `render.yaml`,
`.dockerignore`, `requirements.txt`.

### 1. База данных (обязательно)

На бесплатном тарифе Render файловая система **обнуляется при каждом засыпании
сервиса**, поэтому SQLite-файл там не живёт. Данные хранятся в Postgres:

1. Завести бесплатную базу на [neon.tech](https://neon.tech) (или Postgres на самом
   Render, но там бесплатный период ограничен).
2. Скопировать строку подключения вида
   `postgresql://user:pass@ep-xxx.eu-central-1.aws.neon.tech/neondb?sslmode=require`.
3. Положить её в переменную `DATABASE_URL` в настройках сервиса Render.

Пока `DATABASE_URL` не задана, приложение работает на локальном SQLite —
именно так оно и запускается на вашем компьютере, ничего настраивать не нужно.
Таблицы и список людей создаются сами при первом запуске.

### 2. Сам сервис

1. Выложить репозиторий на GitHub (`data/`, `logs/`, `*.db` уже в `.gitignore` —
   база, ключ подписи и пароли не должны попадать в публичный репозиторий).
2. На Render: **New → Blueprint**, выбрать репозиторий. Render прочитает `render.yaml`
   и создаст веб-сервис на бесплатном тарифе. Либо **New → Web Service → Docker**
   и задать переменные вручную.
3. Переменные окружения:

| Переменная | Значение | Зачем |
|---|---|---|
| `DATABASE_URL` | строка подключения Postgres | **Обязательно на Render.** Без неё данные пропадут при засыпании |
| `APP_TZ` | `Europe/Moscow` | **Обязательно.** Контейнер живёт по UTC, а расписание 19:55 / 20:00–21:00 должно быть московским |
| `SECRET_KEY` | автогенерация | подпись cookie |
| `SECURE_COOKIES` | `1` | Render отдаёт сайт по HTTPS |
| `DEFAULT_PASSWORD` | `a123456` | необязательно, можно задать другой стартовый пароль |
| `DB_CONNECT_TIMEOUT` | `10` | необязательно, сколько секунд ждать базу |

4. Открыть `https://<ваш-сервис>.onrender.com/healthz` — там видно время сервера,
   часовой пояс и какое хранилище используется:

```json
{"status": "ok", "storage": "postgres", "tz": "Europe/Moscow",
 "time": "2026-09-07 20:01:14", "users": 26, "window": "open"}
```

Если `storage` показывает `sqlite` — переменная `DATABASE_URL` не подхватилась.
Если база недоступна, `/healthz` вернёт код 503 и текст ошибки, а сайт не упадёт
в бесконечный перезапуск.

### 3. Холодный старт

После 15 минут без запросов сервис засыпает, первый запрос «будит» его 30–50 секунд.
Заходите в 19:55–20:00: сервис проснётся, выполнит подготовку к новому дню и дальше
час работает без задержек. Данные при этом не теряются — они в Postgres.

## Безопасность

Пароли хранятся только в виде PBKDF2-SHA256 (120 000 итераций) со случайной солью.
Стартовый пароль `a123456` одинаков у всех — попросите участников сменить его при
первом входе, сайт сам об этом напоминает.
В публичный репозиторий не должны попадать `data/lab.db`, `data/secret.key` и `logs/`.
