# Очередь сдачи лабораторной работы

Сайт для выбора места (порядка) сдачи лабораторной работы.
Backend — Python + Flask + SQLite, frontend — Vue 3 (без сборки, файлы лежат в `static/`).

## Быстрый старт

```bash
pip install flask
python init_db.py
python app.py
```

Сайт открывается по адресу `http://localhost:5000`.
Чтобы к нему подключались одногруппники по локальной сети, дайте им адрес
`http://<ваш IP>:5000` (сервер слушает все интерфейсы).

`init_db.py` заводит всех людей из `Люди.txt`, выдаёт каждому пароль из 6 символов
(английские буквы и цифры) и сохраняет список в `data/Пароли.txt` — раздайте пароли участникам.
Повторный запуск безопасен: существующим пользователям пароли не меняются.

Администратор — **Пархачева Екатерина Евгеньевна** (определяется автоматически по списку).

## Распорядок дня

| Время | Что происходит |
|-------|----------------|
| 19:55 | Все пожелания стираются, незакрытые заявки на обмен отменяются, сайт готов к новому дню |
| 20:00–21:00 | Участники входят, выбирают и правят три желаемых места, отвечают на заявки об обмене |
| после 21:00 | Вход для участников закрыт; администратор формирует распределение и отчёт |
| в любое время | Администратор может войти, посмотреть данные, поменять пароль, выгрузить отчёты |

Сброс в 19:55 выполняет фоновый поток. Если сервер в это время был выключен,
сброс произойдёт при первом же обращении к сайту после 19:55 — за день он
срабатывает ровно один раз. Кнопка «Подготовить к новому дню» делает то же вручную.

## Что умеет участник

* войти по фамилии, имени и паролю (`Иванова Анна` + 6 символов);
* выбрать три разных желаемых места очереди и зафиксировать их;
* отредактировать или полностью удалить свои пожелания, пока окно открыто;
* увидеть выданное место после расчёта;
* предложить конкретному человеку поменяться местами;
* согласиться на обмен или отказать; автор может отозвать своё предложение.

## Что умеет администратор

* входить в любое время суток;
* видеть, кто прислал пожелания, а кто нет;
* менять пароль любому участнику — сгенерировать случайный или задать вручную
  (ровно 6 символов, английские буквы и цифры);
* задать количество мест в очереди (по умолчанию — по числу участников);
* включить режим отладки, когда сайт открыт круглосуточно (для проверки);
* запустить расчёт распределения за выбранную дату;
* посмотреть отчёт и журнал, выгрузить их:
  * `Очередь_ГГГГ-ММ-ДД.csv` — место, фамилия, имя, отчество, пожелания, результат, дата формирования;
  * `Журнал_ГГГГ-ММ-ДД.log` — все события за день;
  * `Отчет_ГГГГ-ММ-ДД.zip` — то и другое одним архивом.

## Алгоритм распределения

Задача — раздать каждому ровно одно место так, чтобы как можно больше людей
получили одно из трёх выбранных ими мест. Это классическая задача о назначениях.
Полный перебор для 26 человек нереален (26! вариантов), поэтому применяется
**венгерский алгоритм** (метод Куна — Манкреса, O(n³)): он даёт **ровно тот же
результат, что и перебор**, только мгновенно. В `test_all.py` решение сверяется
с настоящим перебором на случайных наборах.

Стоимость назначения подобрана лексикографически (`assignment.py`):

1. `MISS_W = 100000` — как можно меньше людей вообще без выбранного места;
2. `RANK_W = 1000` — среди остальных: сначала первое пожелание, потом второе, потом третье;
3. `DIST_W = 1` — кому места не хватило, того ставят как можно ближе к желаемому.

Порядок действий:

1. люди, приславшие пожелания, расставляются венгерским алгоритмом оптимально;
2. кто не прислал пожелания до 21:00 — считается, что ему безразлично: такие
   участники случайным образом занимают оставшиеся места;
3. в журнал пишется поимённо, чьё мнение учтено (и какое по счёту пожелание
   сработало), а чьё нет (с указанием ближайшего желаемого места и отклонения).

После расчёта участники могут по обоюдному согласию меняться местами — обмен
меняет места в готовом распределении и полностью протоколируется.

## Проверки

```bash
python test_all.py
```

Покрыто: совпадение с полным перебором, конфликты пожеланий, случайность для
промолчавших, вход и окно 20:00–21:00, фиксация и правка пожеланий, расчёт и
выгрузки, обмен местами (согласие, отказ, чужая заявка), сброс в 19:55, смена
пароля администратором.

## Безопасность

Пароли хранятся только в виде PBKDF2-SHA256 (120 000 итераций) со случайной солью;
`data/Пароли.txt` создаётся один раз для раздачи — храните его отдельно.
Сервер рассчитан на локальную сеть учебной группы; для публикации в интернет
используйте нормальный WSGI-сервер (например, `waitress`) и HTTPS.
